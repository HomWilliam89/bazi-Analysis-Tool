# 01 · 企划

> 性质：工程企划，不是判据。判据以 `规矩\` 为准。
> 本文件只在换期、换范围时改（重级）；平时少动。

## 1. 定位
给定生辰或四柱，输出三样：
1. **排盘事实**——四柱、藏干、十神、神煞、大运、流年等，谁算都一样；
2. **各派并陈**——格局、调候、盲派等各家主张全列，附出处与成立条件，不选边；
3. **本工具看法**——按本工具自己的宪法（乙体系）判断；宪法未覆盖 ⇒ 明写「本体系未覆盖，暂不判断」。

## 2. 组成
| 块 | 内容 | 原料 | 状态 |
|---|---|---|---|
| 底座 | 排盘（沿用现成已验证实现，不改） | 现成实现 | 期 2 接入 |
| 丙层 | 各派主张库：主张／出处／成立条件 | 使用者自制的古籍 md | 期 3 |
| 乙体系 | 本工具宪法：从零长，起步只有几条 | 使用者口述＋逐条讨论 | 期 4 起 |

## 3. 分期
| 期 | 做什么 | 交付物 | 出口条件 |
|---|---|---|---|
| 0 | 立项 | 四件文档定稿 | ✅ 已完成 |
| 1 | 骨架 | 目录、AGENTS、两个工具、git | ✅ 工具自检绿 |
| 2 | 底座 | 排盘接入、验证 | 排盘输出全绿 |
| 3 | 古籍与流派库 | 接收古籍 md → 校验 → 丙层各派条目 | 每条出处可查 |
| 4 | 宪法与案例 | 乙体系宪法初稿＋案例钉住 | 案例全绿 |
| 5 | 集成交付 | 技能集成、独立审查 | 验收标准全过 |

## 4. 乙体系的生长机制
每条新判据四步：讨论 → 裁定（台账）→ 钉住（案例）→ 入库（`规矩\`）。
宪法只增改、不推翻；要推翻＝重级，先讨论。

## 5. 验收标准
- 案例跑器全绿；改判据必须带新案例；
- 同盘独立复核：乙部分结论一致；
- 丙部分每条主张出处可查，查不到写「未检得」；
- 收口检查全绿（禁词与编码检查，见 `文档\03` §4）；
- 交付前测试全绿；失败分类处置见 `AGENTS.md` §6。

## 6. 风险与对策
| 风险 | 对策 |
|---|---|
| 流程太重被绕过 | 分级闸门（轻级免全套）；闸门本身不设例外 |
| 宪法长太快、互相打架 | 每条判据四步齐备才入库；术语一词一义 |
| 教训丢失 | git 历史＋台账＋日志；正文不留沿革 |
| 古籍 md 质量参差 | 接收规格＋校验器＋原件留底 |
| 只改一侧（正本／镜像） | 一律走同步脚本分发；禁止手工复制 |
