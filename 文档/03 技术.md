# 03 · 技术

> 性质：工程方案。管目录、命名、案例、测试、git、编码纪律。
> 判据相关规则以 `文档\02`、`规矩\` 为准。

## 1. 目录树
```
八字分析工具\
├─ AGENTS.md              ← 硬纪律＋指路（每轮自动进上下文；英文名固定）
├─ README.md              ← 项目说明（英文名惯例）
├─ 文档\                  01 企划 · 02 设计 · 03 技术 · 04 决策台账
├─ 核心\                  排盘底座（期 2 接入，不改实现）
├─ 规矩\                  乙体系：宪法＋判据＋术语（判据唯一处）
├─ 流派\                  丙层：各派主张库
├─ 古籍\                  使用者自制的古籍 md（接收规格见其 README）
├─ 案例\                  命盘案例（*.jsonl）
├─ 工具\                  case-runner.mjs · shoukou-check.mjs
└─ 日志\                  YYYY-MM-DD.md
```

## 2. 命名
- 目录与文档：中文；代码文件：英文（小驼峰函数、kebab 文件名）。
- 判据 ID `P-###`；案例 ID `C-###`；决策 ID `D-###`。全仓唯一。

## 3. 编码纪律
1. UTF-8 无 BOM；禁用 PowerShell Set-Content 写中文文件。
2. git `core.quotepath false`（已配）。
3. 脚本只用相对路径定位（`fileURLToPath(import.meta.url)` 起算）。
4. 根级 `AGENTS.md`／`README.md` 保持英文名。

## 4. 工具
- `shoukou-check.mjs`：收口检查——对 `文档\`、`规矩\`、`流派\`、根级两文件逐行查
  **禁词**（清单维护在脚本内）、BOM、非 UTF-8 乱码。退出码 0／1。
- `case-runner.mjs`：案例校验——`案例\*.jsonl` 逐行 schema 检查、id 唯一、期望 null 规则；
  判据建成后升级为真跑（读引擎、比期望）。

## 5. 测试矩阵（交付前全跑）
| 命令 | 验什么 |
|---|---|
| `node 工具\shoukou-check.mjs` | 收口／编码 |
| `node 工具\case-runner.mjs` | 案例格式（后期：判据回归） |
| `node 核心\selftest.mjs` | 底座全绿（1149 项全量验证） |

全绿才可交付；失败分类处置见 `AGENTS.md` §6。

## 6. git 约定
- 一逻辑改动一 commit；文档＋判据＋代码＋案例同 commit；提交前测试全绿。
- message：`[轻|中|重] <判据ID或D-###>: 一句话`；正文四行：改了什么／为什么／影响面／测试。
- 分支 main 单线；每期结束打 tag（如 `v1-skeleton`）。
- 回滚以 commit 为单位；本地 commit 或 amend 后必须同步核准日志记录之 commit hash；严禁未经使用者明确同意执行 git push；`reset --hard`／强推前必须先问使用者。

## 10. 引擎量化参数说明
底座引擎内部包含部分用于计算机连续打分之工程量化参数（如：宫位权重月支 0.35、日支 0.20；干支位置距离衰减贴身 1.00、隔位 0.55、遥隔 0.25；五行力量占比阈值等）：
- **定位**：此类参数属于算法实现的**工程操作化近似数值**，绝不作为乙体系之宪法判据。
- **纪律**：宪法所定者为序（如“月令最大，时支其次；通关桥须两端贴身”）；底层数值之微调不视为易学宪法改动。
