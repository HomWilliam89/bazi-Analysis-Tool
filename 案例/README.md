# 案例\ — 命盘案例（判据的回归网）

## 案例是什么
某判据的机器可读锚点：给定盘，期望输出必须与 `规矩\` 判据一致。
跑不过 ⇒ 要么代码 bug（A 类），要么判据与期望打架（B 类：停下问使用者）。

## 格式（JSONL，UTF-8，一行一个案例）
```json
{"id":"C-001","判据":["P-001"],"盘":{"ganzhi":["甲子","乙丑","丙寅","丁卯"]},"期望":{"判定":"…"},"说明":"钉住 P-001"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| id | 是 | `C-###`，全仓唯一 |
| 判据 | 是 | 判据 ID 数组（一个案例可钉多个判据） |
| 盘 | 是 | `{"ganzhi":[年,月,日,时]}` 或 `{"birth":"YYYY-MM-DD HH:MM","gender":"男"}` |
| 期望 | 是 | 枚举结论对象；**未裁定 ⇒ null**，且 `说明` 必须挂决策编号 |
| 说明 | 否 | 为什么值得钉住（期望为 null 时必填） |

## 规矩
- 每条判据至少 1 个案例；改判据（中/重级）必须新增或更新案例。
- **禁止改期望值让测试绿**（＝`AGENTS.md` §6 B 类：停 → 台账 → 问使用者）。
- 事实字段（`盘`）改动先问。
- 跑法：`node 工具\case-runner.mjs`。
